| 🏯 七下·中国古代史（隋唐—明清前期） | 隋唐繁荣开放、宋元民族关系与经济发展、明清统一多民族国家 | 3 |

| 🌍 九上·世界古代与近代史 | 古代亚非欧文明、封建时代、走向近代、资本主义制度初步确立 | 7 |

| 📝 中考模拟考试（整卷） | 按广州中考结构命题的整卷，60 分钟计时、交卷才批改 | 2 套 |

**每条内容的八块结构**（`HistoryDetail` 按备考顺序渲染，`pnpm validate` 逐条检查是否写全）：

1. **主线一句话**——先立骨架（「秦朝首次建立统一多民族的中央集权国家，但因暴政速亡；汉承秦制而与民休息……」）；
2. **⏳ 时空坐标**——时间轴上标出必背节点（`key` 加重显示），时序观念是历史选择题的第一考点；
3. **📌 考点分层**——每条考点标为 `重点 / 次重点 / 了解`，并给「为什么考、怎么答」；摘要栏可一键**只看重点**，总复习时先啃这一档；
4. **🧠 必背结论与答题术语**——材料题能直接用的句子（「落后就要挨打」「没有共产党就没有新中国」要有史实支撑地写出来）；
5. **⚠️ 易错易混**——命题人爱设的陷阱，用「✘ 常见错误 / ✔ 正确理解 / 为什么容易错」三行写清；
6. **🔀 关联与对比**（表格）——中外对比与跨册对比（西周分封制 vs 秦朝郡县制、郑和下西洋 vs 新航路开辟、洋务运动 vs 明治维新、苏联改革 vs 中国改革开放……），这是历史大题的核心能力；
7. **📊 命题角度与考法**——按考点整理「怎么考」（史料判断、时序排列、因果分析、比较联系……），并**明确标注这是复习研判而非官方统计**；
8. **✍️ 材料大题**（阅读材料，回答问题）——对应广州中考非选择题形态：材料 + 设问（带分值）+ 参考答案 + 踩分点，可先自己写再对照。

**两块备考专用内容**：

- **📊 考点与考情总复习**（`/history-review`）：把六册与专题的全部考点摊成一张总表——先讲清广州中考历史**怎么考**（结构、时长、评分方式），再按三档列考点（可只看重点、可展开全部），最后把**全部命题角度与材料大题**索引出来，直达对应内容。数据全部由内容聚合而来，不会出现「考点表与课文对不上」。
- **📝 整卷模拟考试**（`/exam-run/:paperId`）：练的是**时间分配与整卷节奏**，这是单题练习给不了的能力。因此与练习引擎分开实现：卷面顺序固定、有**答题卡**可跳题回改、全程只有倒计时、交卷前不给任何正误反馈、时间到自动交卷；交卷后选择题自动判分、材料题给出参考答案与踩分点后**自评**，成绩单给出「选择得分 / 材料题自评得分 / 用时」与逐题解析，错题照常进错题本。

**结构照官方文件设置**（`pnpm validate` 会验卷）：2027—2029 年广州中考历史为 **70 分**（原 90 分，属「适当减分」科目）、**闭卷笔试 60 分钟**、与道德与法治同场分卷，试卷结构为 **单项选择 20 小题 40 分 + 非选择题（阅读材料，回答问题）3 小题 30 分**（依据：广州市教育局《2027—2029 年广州市初中学业水平考试录取计分科目考试实施方案》，穗教规字〔2025〕1 号）。校验器里的 `HISTORY_STRUCTURE` 常量就是这份结构；官方若调整分值，改数据即可，代码不用动。

### 学习机制

- **练习引擎**：选择题、填空题与简答题统一判分，选择题选项每次练习都会重新打乱，避免靠位置记忆。
- **三种题型**：`choice` 四选一即时判分；`fill` 填空（忽略标点与空白，支持 `|` 备选写法）；`short` 简答题（揭示参考答案与踩分点后自评），对应广州中考名著附加题的真实考法。
- **默写题粒度自适应**：各篇 `lines` 的拆分粒度并不统一（近体诗按「联」、文言文常按长句或段落），若整行挖空会出现「一次默写 99 个字」的荒唐题目。因此默写题一律由 `makeReciteQuestions()` 下沉到「句」一级生成，用相邻句作上下句提示，并按字数给出难度。
- **即时解析**：每题作答后立刻给出对错、正确答案与解析，并标注知识点标签。
- **填空容错**：默写判定忽略标点与空白，只比对汉字，答案支持多种可接受写法（`|` 分隔）。
- **错题本**：自动收集错题，按模块归类；答对一次即减少计数、答对后自动移出；支持「只练错题」与整组重做。
- **学习进度**：每条内容的打开次数、答题正确率、最近学习时间、收藏、背诵打卡次数。
- **每日打卡与连续天数**：打开应用即完成当日打卡，顶栏显示连续天数。
- **学习报告**：总览数据、近 14 天答题趋势图、各模块完成度、由错题标签自动聚合的薄弱知识点、收藏列表。
- **学段切换**：七上 / 七下 / 八上 / 八下 / 九上 / 九下 / 全部，模块内容与练习范围同步切换。
- **全局检索**：模块内可按关键词与标签筛选。
- **朗读（整页 / 逐段）**：任意详情页顶部都有一条朗读控制条，段落由条目数据推导（古诗逐句、文言文逐段、现代文逐段、作文与文学常识读正文与要点），可暂停/继续/停止、切上一段下一段；语速 0.6×–1.8× 与音色可调并记住选择。古诗词与文言文的**每一句旁边另有一个 🔊**，只读那一句。引擎用的是浏览器/系统自带的中文语音（Web Speech API）：**免费、无需密钥、断网也能用**；若某台设备没有中文语音会给出提示，而不是静默失败。
- **逐词释义（悬停/点按看解释）**：正文里需要翻译的字词带虚线下划线，鼠标悬停（手机点按）弹出释义气泡。数据来自文言文的注释与语法归类、古诗词的逐句串讲（「临：登上；碣石：山名…」）。只有整句译文、没有逐词释义的 65 首（八上、九上九下一批）改用其「默写易错点」里的字词兜底，气泡标成【易错】以区别于【释义】——讲的是字形与读音，不是意思。
- **背诵四级、按小段遮罩**：① 通读全文 → ② 首字提示 → ③ **逐段遮罩** → ④ 完全遮住。第三级把每句按标点切成小段（六字以内的小句自成一段，如「枯藤老树昏鸦」；更长的按 5 个汉字再断），**五言绝句就是五个字一小段**，可单点某一段遮住，也可以「🎲 隔段遮」遮一半留一半当提示——不必整行一起遮。
- **练完能学回去**：每道题作答后（以及结果页的错题回顾里）都有「📖 回知识点：XXX」直接跳到这道题的来源内容，旁边「🧩 关联知识（N）」展开这道题牵出的其它初中知识点（同作者、同一考点、本篇字词、相关文学常识），每条都能点进去——练习页因此不必为了这个入口多加载模块。
- **响应式**：桌面为顶栏导航，手机为底部标签栏，竖排古诗文在窄屏自动调整间距。

数据全部保存在 `localStorage`（键名 `xueer.study.state.v1`），不上传任何服务器，可在「学习报告」页一键清空。

### 常规讲解之外的三种辅助

除了每个模块的常规讲解，还有一层「知识拓展」，用于**联想记忆**与**加深理解**：
思维导图（看脉络）、拓展阅读（看背景），以及把知识点互相串起来的**学一补多**（见下文）。

#### 🧠 思维导图（32 张 / 1113 个节点）

以横向树状图呈现知识脉络，根节点居中、分支向右展开，三级结构。**每个节点都带 `note`**（义项、例句、数字、名句或记忆口诀），这是导图能辅助记忆的关键。

- **折叠交互**：点任意节点展开／收起；工具栏有「展开全部」与「只看主干」，方便先看骨架再逐层回忆。
- **记忆钩子**：多处写入口诀，例如
  - 《朝花夕拾》篇目：「狗·阿·二·五·无，百·父·琐·藤·范」
  - 《骆驼祥子》三起三落：「车—抢—钱—骗—车—卖」
  - 文言虚词「之」：「的、代、取独、提宾、往、凑音」
  - 修辞辨析：「两项相等是对偶，三项以上是排比；自问自答是设问，答在问中是反问」
- **覆盖范围**：12 部名著各 1 张 + 名著人物关系总览 1 张；文言虚词体系、文言语法五大现象、文言翻译六字诀、九上文言名篇；古诗意象／主题／手法／体裁／默写易错字／九上诗词曲；八种修辞、字音字形规律、成语误用六类、作文结构模板、审题立意四步、语言出彩五招、现代文阅读答题思路、广州中考试卷结构。
- **两份取材**：在名著／内容详情页会展示**精确绑定**该条目的导图；若没有绑定，则回退展示**本模块的体系性导图**（默认只显示主干，避免页面过长）。

### 按中考要求组织的六个入口

「不只是跟着课文走，而是对着中考学」——这几块就是为此而建：

#### 🔗 知识联动（内容详情页自动生成）

每个内容页底部都有「关联学习」，**说明为什么相关**，而不是随机推荐：

| 关联类型 | 例子 |
| --- | --- |
| **同作者**（最强信号） | 《观沧海》→《龟虽寿》（同为曹操）；《夜雨寄北》→《无题》《贾生》（同为李商隐） |
| **同主题** | 《次北固山下》→《渡荆门送别》《商山早行》（同为思乡） |
| **同意象** | 《天净沙·秋思》→《使至塞上》（同用「夕阳」） |

关联由既有数据推导（作者、主题标签、从诗句中识别出的意象），并做了两层降噪：**出现比例过高的标签**（如「写景」）不予采用；**宽泛标签**（如「抒情」）必须另有强信号支撑——否则会出现「唐诗因为都『抒情』而关联到现代诗」这种没有教学价值的推荐。

#### 🧩 学一补多（跨模块串知识点）

「关联学习」解决的是**同类作品之间的横向比较**；「学一补多」解决的是另一件事：**学一篇时，顺带把其它模块的同源知识点一起补上**。它出现在每个内容页「关联学习」的正下方，按分组列出，每组都写明「补什么」。分组沿用拓展阅读那套折叠样式（默认只展开第一组，右上角有「展开全部」），否则一个文言文条目的末尾会一下子铺开十几行。

| 分组 | 从哪里来 | 例子（《陋室铭》文言文版） |
| --- | --- | --- |
| **同一作品·其他模块** | 同一篇在别的模块还有一份，学法不同 | → 古诗词模块的《陋室铭》（逐句默写用） |
| **同作者·某某** | 同一作者的其它作品，跨模块（诗文一起看） | → 刘禹锡《秋词（其一）》《酬乐天扬州初逢席上见赠》 |
| **同一考点** | 考同一批知识点，可连起来做专项 | → 《爱莲说》《岳阳楼记》；并给出「🎯 就『宾语前置』做考点专项」直达链接 |
| **本篇涉及的字词** | 本篇正文里真的出现了该字词/成语条目 | → 顺手把释义补上 |
| **相关文学常识** | 作者名／篇名／出处名，或**文体名**命中常识条目 | → 「刘禹锡——有『诗豪』之称的唐代文学家」 |
| **同类作品·横向比较** | 同主题 / 同意象 | → 交给「关联学习」的规则，不重复推荐 |

**相关文学常识**是三路匹配，按可信度排序：名字命中**标题**（「李白——诗仙」）> 名字命中**必记要点** > **文体名**命中标题且该条属「文学体裁」类。第三条让现代文阅读的每一篇也补得上文体常识——《最后一班车》（小说）补「小说：三要素与发展脉络」，《秋天的声音》（散文）补「散文：叙事、抒情与哲理」，议论文与说明文补「记叙文、说明文与议论文文体常识」。文体名用的是**白名单**（记叙文/说明文/议论文/散文/小说/戏剧/诗歌/现代诗/文言文/非连续性文本/新闻/寓言/童话/传记），而不是「标签里长度 ≥2 就用」——否则古诗文的主题标签「叙事」「写人」会误勾到《散文：叙事、抒情与哲理》。

三条降噪规则同样是回归测试的对象：

1. **考点必须「有区分度」**：每个知识点的权重按 `1/出现条目数` 计算（越稀有越有价值），并要求至少命中 1 个稀有标签才成组——否则任何两篇文言文都会因为「实词、注释」而互相关联。题库共 839 个知识点标签，正是这条规则把「同一考点」从 944 条压到 539 条有意义的关联。
2. **文学常识只在「标题 + 必记要点」里匹配**，不拿整篇 `content` 去匹配作者名——否则一处顺带提及就会造成假关联；命中标题的排在只在要点里提一句的前面。
3. **「作者」为占位值时不成组**（佚名、无名氏），避免出现「同作者·佚名」这种空标题；而以书名作作者的（《诗经》《礼记》《吕氏春秋》《古诗十九首》）改用「同一出处」的说法，并且去掉书名号后再匹配（常识条目里写作「《诗经》是我国第一部诗歌总集」）。
4. **一页之内同一篇作品只出现一次**：库里同一篇常有古诗词版（默写用）与文言文版（讲读用）两份，只按 id 去重会出现「同作者」组里一条《诫子书》、《同类作品》组里又一条的尴尬情形，因此按**标题**去重、先出现的分组先占位。
5. **文体匹配要收敛**：只有白名单里的文体名才算，且只认「文学体裁」类条目的标题——否则《西游记——吴承恩神话小说》会因为标题里有「小说」而被每一篇小说类选文勾中。

`pnpm validate` 对这两套联动规则做结构回归：分组完整（`kind`/`hint`/非空 `items`）、不自我指涉、不重复推荐、**同一页不出现两条同名条目**、指向真实存在的条目、**「同一作品」关系必须对称**（A 指向 B，B 必须回指 A）、**每一条作家作品与文体常识都必须至少被一条内容关联到**（防止作者名对不上导致内容白写），并打印 2583 条学一补多关联、2149 条关联学习、以及 84 条文学常识中 68 条有入边的分布。`pnpm smoke` 则断言《陋室铭》详情页真的渲染出跨模块分组与考点专项入口——光跑路由渲染发现不了「组件没接进 `DetailShell`」这类漏接。

当前每个条目平均补出 5.3 个知识点，**478 个条目全部都能补出至少一个**。

#### 📅 今日背诵（间隔重复）

`/recite` 按遗忘规律安排复习：背对一次升一档，间隔 1 → 2 → 4 → 7 → 15 → 30 天；背错降档、次日重来。

#### 🧠 课时思维导图（每一课都有）

原来只有 32 张**人工整理的体系图**（文言虚词体系、名著人物关系…），而一首古诗、一篇文言文打开时往往看不到图。现在**每一课都有自己的思维导图**——由 `src/lib/lessonMaps.ts` 从条目自身数据**推导**出来，因此覆盖语文全部 **464 个条目**（121 首古诗词、73 条字词、26 篇文言文、48 篇现代文、82 条作文、114 条文学常识），不必逐条手写，也不会随内容更新而失效。

每张图沿用同一个骨架，学生换一课不用重新适应：

```
中心（课题）
 ├─ 这一课是什么        作者/出处/文体/年级
 ├─ 内容脉络            诗词按句串（带逐句注释）、文言文按段落
 ├─ 必记要点            名句 / 重点实词 / 语法归类（通假字、古今异义、词类活用…）
 ├─ 手法与情感          从赏析里拆出的要点
 ├─ 易错字与易混点      每条取「引用词」当标签、完整说明放进节点注释
 └─ 中考考点            从赏析末尾的「中考考点：①②③」拆成分支，可直接背
```

节点标签保持短（长了整张图会被撑宽扫不动），完整释义放进节点下方的注释——例如「易错字」分支显示「式微｜「式微」的「微」指昏暗；「微君之故」的「微」是「非，不是」……」，扫得动也看得全。详情页优先显示**本课图**，没有人工绑定图时才用它；人工图（如 12 部名著的人物·情节图）仍然优先。

`pnpm validate` 逐条生成并检查：六个模块覆盖率必须 100%（某一课数据缺了会让图静默变空）、节点文字 ≤30 字、层级 ≤5 层。`pnpm smoke` 断言古诗与文言文详情页真的渲染出「本课思维导图」且节点数 ≥5。

#### 🎯 中考考点（按考点刷题）

`/exam` 从题库的知识点标签**自动聚合出考点索引**——因此考点与题目天然对应，不会出现「考点没有题」。每个考点显示题量与题型分布、涉及的内容条目、**我在这个考点的错题数**。

**每个考点都既有「学」也有「练」**（不能只给一个刷题入口）：

| 按钮 | 作用 |
| --- | --- |
| 📖 **先学一遍** | 跳到该考点的第一条内容详情页——那里有讲解、课时思维导图、易错点 |
| 📚 **看相关 N 条** | 跳到模块列表页并**按该考点筛好**（模块页支持 `?tag=` 直连） |
| ✍️ **专项训练** | 只刷这个考点的题 |

**古诗词另有一套考点。** 古诗词模块不预置题目（默写题由逐句现场生成），所以它没有任何题目标签，在「按题目标签聚合」的体系里会**整体缺席**——而古诗文恰恰是中考默写与鉴赏的重头。因此为它单独建了 **97 个聚类考点**，三种来源：

| 聚类方式 | 例子 | 一键训练 |
| --- | --- | --- |
| **主题** | 主题·思乡（由篇目标签得来，已排除「抒情」「写景」等宽泛词） | ✍️ 默写这 N 首 |
| **意象** | 意象·月、意象·杨柳（由诗句文本自动识别） | ✍️ 默写这 N 首 |
| **作者** | 作者·李白、作者·《诗经》 | ✍️ 默写这 N 首 |

每个考点卡片还会列出该簇的篇目（可点进详情看赏析），并且用 `/practice/poems?poems=<id,…>` **只默写这一簇**——这条按篇目组卷的路由是为它新加的。考点覆盖 115 / 121 首。`pnpm smoke` 会断言这条链路真的通：点某考点的「默写这 N 首」后，页面标题是「默写专项」且题量**正好等于这几首的逐句默写题数**（不然会静默退化成「按学段随机默写」，学生点了考点却默写了别的篇目）。

**两处性能取舍**（考点已有 660 个，一次全铺会把页面撑到近 400 KB HTML、手机上必卡）：

- 每个模块先只渲染前 12 个考点，点「展开全部 N 个考点」再看剩下的；古诗词分区按「主题/意象/作者」三类各显示前 8 个，保证三类都露头。**一旦输入搜索词就全部展开**——搜索本身就是「我要找某个点」的意图。改动后 `/exam` 的渲染量从 **398 KB 降到 66 KB**。
- `pnpm smoke` 断言该页真的渲染出古诗词分区与「默写这 N 首」链接（这类漏接靠路由渲染发现不了）。

#### 📚 整本书阅读：把 12 部名著串成一条线

学生读名著最大的问题是**「整本书太散、记不住」**——人物、情节、主题各自成卡片，却没有一条线把它们串起来。因此为 12 部必读名著各补三块内容（数据在 `books-plot-1/2/3.ts`，按条目 id 合并回名著条目，共 **128 个章节板块 · 101 环情节主线 · 36 条记忆口诀**）：

| 内容 | 作用 |
| --- | --- |
| **情节主线**（8–9 环） | 一环一句话，按顺序排成一条**可见的链**（带连接线），读一遍全书骨架就立住了；答题时先想「在哪一环」再调细节 |
| **章节脉络**（9–12 条） | 按这本书**真实的结构**逐段串下来：小说按回目/情节段、《朝花夕拾》按单篇（小引+10 篇+后记）、《经典常谈》按 13 篇（末两篇合为一条）、《昆虫记》按虫类、《唐诗三百首》按体裁分卷 |
| **记忆口诀**（3 条） | 真的能用的口诀，例如《西游记》收徒顺序「猴—马—猪—沙」+ 结构「七、五、九九八十一、一」；《水浒传》好汉出场「鲁→林→杨→宋」；《儒林外史》「周进哭、范进疯、严监生两根灯草、匡超人变质」 |

**考点按广州中考「整本书阅读」的考查面统一成 9 类**（`src/lib/bookExams.ts` 里的受控词表）：情节梳理 · 人物形象 · 人物关系 · 细节辨识 · 主题探究 · 艺术特色 · 跨书比较 · 联系实际 · 作品常识。

为什么要受控词表：题目的 tags 会被「中考考点」页聚合成考点卡片，若每道题各写各的（「情节」/「情节梳理」/「梳理情节」…），页面上就会出现一堆只有一两道题的碎片考点。现在名著的题一律从这 9 类里选，书名与人物名只作筛选用——**连原有的 36 道广州风格简答题也一并做了标签规范化**（把 `读书笔记`/`人物辨识`/`人物小传`/`专题探究`/`启示` 等临时标签换成受控考点），29 道题因此重新归类。

名著详情页因此多了「本部考点（广州中考标准）」一栏：列出这部书实际考到的考点与题量，**点任一考点只练这一部书的这一类题**（`/practice/literature/<id>?tag=<考点>`），末尾还有「练这部书全部 N 题」与「看全部名著考点」两个入口。14 部带 `book` 的条目共 160 道题，其中 122 道挂了受控考点；考点分布（可挂 2 个，故计数大于题数）：人物形象 37 · 细节辨识 23 · 主题探究 22 · 情节梳理 19 · 跨书比较 18 · 作品常识 18 · 联系实际 13 · 艺术特色 12 · 人物关系 8。

13 部名著的**自有测验题**（每部 3–6 道，如《西游记》的「作者是谁」这类）沿用的是「文化常识 / 文学体裁 / 作品归类」等知识点标签，**没有**改成这 9 类考点——它们问的是文学常识而不是整本书阅读，硬套考点反而失真。

`pnpm validate` 逐部核对：章节 ≥8 条、情节主线 ≥6 环、口诀 ≥2 条、考点题 ≥6 道（其中简答 ≥2 道且都带踩分点）、覆盖 ≥4 类考点、每道题都用了受控考点词；**并且列出「必读名著里还没有章节脉络的」**——挂接 id 写错会导致数据静默失效（页面照常渲染，只是那部书什么都没有），这类问题只能靠显式检查拦住。`pnpm smoke` 则断言名著详情页真的渲染出这四块并带考点专项链接。

#### ✍️ 作文板块（从「只讲方法」扩到「能练」）

原作文模块只有方法讲解，学生**没有题可写**。现扩至 82 条，新增三个类别：

| 类别 | 条数 | 作用 |
| --- | ---: | --- |
| **作文题库** | 26 | 命题 8 · 半命题 7 · 材料 6 · 话题 5。每题含审题（**含两种跑偏理解及为何不对**）、三个层次的立意、具体选材方向、可套用提纲与字数配比、写作任务提示、原创开头示例 |
| **升格训练** | 9 | 同一篇的平庸版与升格版对照，逐处说明「原句 → 改句 → 为什么更好」 |
| **范文点评** | 12 | 12 篇完整原创范文（600-800 字），点评**指认具体句子**的得失，而非泛泛说「语言优美」 |
| 考场技巧 | 6 | 时间分配、字数卷面、拟题法、开头结尾范式、写不出来怎么办 |
| 文体写作 | 6 | 议论文（论点/论据/论证 + 并列·递进·对照结构）、说明文、演讲稿与书信、读后感 |

范文刻意保留少量稚嫩处（议论偏直、概括交代句），因为**每篇都完美的范文学生学不来**。

**古诗文对齐《义务教育语文课程标准（2022年版）》**：7~9 年级背诵推荐篇目 60 篇（段）已**全部收录**。文言文 26 篇均含 12 条以上重点注释，并按通假字 / 古今异义 / 词类活用 / 一词多义 / 特殊句式分类整理；名著导读 12 部均含人物、经典情节、主题与艺术特色结构化数据。

## 三、数据契约

所有内容最终都会装配成统一的 `Entry`（见 `src/types.ts`），因此**列表页、练习引擎、错题本、统计只需要一套实现**：

```ts
type Entry =
  | { moduleId: 'poems';      data: Poem }
  | { moduleId: 'vocab';      data: VocabItem }
  | { moduleId: 'classical';  data: ClassicalText }
  | { moduleId: 'reading';    data: ReadingPassage }
  | { moduleId: 'writing';    data: WritingLesson }
  | { moduleId: 'literature'; data: LiteratureItem };

// 公共字段：id / title / subtitle / grade / tags / searchText / questions
```

练习题统一为 `QuizQuestion`：

```ts
{
  id, type: 'choice' | 'fill' | 'short', stem, options?, answer,
  explanation, difficulty?, tags?, rubric?
}
```

- `choice`：**恰好 4 个选项**，`answer` 为 `'A' | 'B' | 'C' | 'D'`。
- `fill`：**不设 options**，`answer` 为精确文本；多种可接受写法用半角 `|` 分隔。
- `short`：**不设 options**，`answer` 为参考答案，`rubric` 为踩分点数组，供学生对照自评。

`pnpm validate` 会检查 id 全局唯一、字段完整性、选项数量、答案合法性、`lineNotes` 与 `lines` 数量一致、简答题必须有踩分点等规则，并输出各模块内容量与题目量统计。

## 四、如何扩展

### 增加语文内容

在 `src/data/chinese/` 下对应文件里按接口追加条目即可，无需改动任何 UI 代码 —— 列表、检索、组卷、错题、统计会自动包含新内容。追加后跑 `pnpm check`。

### 新增学科

架构已做成学科无关：页面只依赖 `src/data/index.ts` 提供的聚合 API，**新增学科时 UI 一行都不用改**。

1. 在 `src/types.ts` 的 `ModuleId` 联合类型中加入该学科的模块 id，并定义该学科的内容模型（如数学的 `MathTopic`）与 Entry 变体。
2. 新建 `src/data/<subject>/index.ts`，把数据装配成 `Entry[]`，导出 `allEntries` / `mindMaps` / `extensions`。
3. 在 `src/data/index.ts` 中 `import` 并展开到全局聚合里（三行）。
4. 在 `src/data/subjects.ts` 里把该学科的 `available` 置为 `true` 并填好 `modules` —— 首页、学科页、统计页会自动出现它。
5. 如有专有呈现方式，在 `src/pages/detail/` 增加渲染器并在 `DetailPage.tsx` 的 `switch` 中注册。

首页、学科页、模块列表页、练习页、错题本、统计页与知识拓展页都是数据驱动的；`scripts/validate-entry.ts` 与 `scripts/smoke-entry.tsx` 也已遍历全部学科，新学科的数据与页面会自动纳入校验。知识联动（`src/lib/relations.ts`）同样只依赖统一 `Entry`，新学科无需另写关联代码——但要注意它**只在同学科内建立关联**，数学与语文的知识点不会混在一起。

## 五、实现说明

- **技术栈**：Vite + React 18 + TypeScript。路由用 `HashRouter`，因此部署到任意静态托管（含子目录）都不需要服务端 rewrite 规则；`base: './'` 让资源路径为相对路径。
- **关于直接打开 `dist/index.html`**：不可以。浏览器为安全起见禁止通过 `file://` 加载 ES 模块（`type="module"`），请用 `pnpm dev` 或 `pnpm preview` 通过 http 访问。
- **样式**：手写 CSS 设计系统，CSS 变量统一管理配色与圆角阴影；配色取「宣纸 + 墨 + 朱砂 + 黛蓝」，古诗文用楷体/宋体呈现，正文用系统无衬线字体。
- **打包与代码分割（首屏 gzip 从 1527 kB 降到 151 kB）**：内容文本占了整个应用体积的九成以上（源码合计约 4.5 MB），因此数据层做成**按需加载**：
  - 每个模块的数据在 `src/data/chinese/modules/*.ts` 里，由 `data/chinese/index.ts` 动态 `import`；页面开头用 `useDataScope([...])` 声明自己需要哪些模块，打开古诗词就不会下载作文与名著那几块。
  - 对外**仍是同步 API**：`allEntries` / `entriesOfModule` 等容器改成**原地填充**（`push` 而非重新赋值，引用恒定），页面渲染代码基本不用改；校验脚本（validate / smoke）在断言前统一 `await ensureAll()`，因此既有的「渲染出真实内容」检查全部保留。
  - **首页与学科页**是总览页，只要几个数字，不该为它下载全部正文：它们读 `src/data/summary.ts` 这份**生成**的轻量清单（条目骨架 + 模块汇总 + 每日一句池 + **关联索引**，46 kB gzip）。清单由 `pnpm gen` 生成，`pnpm validate` 会逐项比对它与真实数据，**过期直接报错**。
    - 关联索引是为「🧩 学一补多 / 🔗 关联学习」准备的：详情页常只加载**一个**模块，跨模块分组（同一作品的其他模块版本、同作者、同一考点、本篇字词、相关文学常识）若只能看见已加载的模块，就会**静默变少**——服务端渲染的校验脚本因为预加载了全量数据，反而查不出来。做法是把关联规则读到的那几个字段（作者、题目考点标签、意象名、词条名、文学常识命中表）一并对齐进清单，**已加载的条目用完整数据、未加载的用清单骨架**，两条路径结果逐条比对（`pnpm validate` 的「按需加载一致性」一行，0 条不一致）。
    - 其中「相关文学常识」的命中关系是**生成阶段算好的**（`EntryMeta.matchFrom`）：它需要全库的作者名与篇名表（「咏雪」这样的篇名不带书名号），浏览器里只加载一个模块算不全，于是拿全量数据算一次存进清单，运行期查表；打分规则仍是 `lib/relations.ts` 的 `litScoreFor`，生成与校验共用同一份。
  - **KaTeX**（渲染器 + 样式 + 字体约 76 kB gzip JS + 8 kB CSS）单独成块，只有数学详情页懒加载它；`main.tsx` 不再全局引它的样式，`RichText` 在文本里没有 `$` 时完全不触碰它（语文内容没有任何公式）。
  - 框架分成独立块（react 44.5 kB / router 5.0 kB / vendor 4.2 kB），只改内容时这些文件名不变、浏览器直接命中缓存。
  - 实测各页首屏 gzip：**首页 151 kB**；模块列表页 186–431 kB（按模块大小）；详情页再加导图与拓展那块 130 kB。

| 页面 | 首屏 gzip | 说明 |
| --- | ---: | --- |
| 首页 | **151 kB** | 只用轻量清单，不含任何正文 |
| 字词模块页 | 187 kB | 151 + 字词 36 |
| 古诗词 / 文言文模块页 | 291 / 297 kB | 151 + 140 / 146 |
| 阅读 / 文学常识 / 作文模块页 | 367 / 426 / 435 kB | 151 + 216 / 275 / 284 |
| 任意详情页 | 上列 + 130 kB | 另加思维导图与拓展阅读 |
| 数学页（界面隐藏） | 另加 205 kB 数据 + 78 kB KaTeX | 语文学生永不下载 |

  - 一处刻意的取舍：**页面本身不做懒加载**。它们每个只有几 KB，拆出去省不下多少，却会让 `pnpm smoke` 的服务端渲染只拿到 Suspense 占位符、看不到真实内容——那等于把最有价值的一层回归测试弄瞎。同理，语文六个详情渲染器保持静态引入，只把数学那一个拆出去。
  - 另外两处踩过的坑，都已固化成检查：① 校验入口若**静态** import 某个动态块里的数据文件（如 `books-plot-*.ts`），会形成「入口 → 动态块 → 入口」的循环，而入口有顶层 await，结果是 `Detected unsettled top-level await` 卡死——现在改成校验加载后的合并结果；② 页面若读了内容数据却忘了声明 `useDataScope`，在浏览器里会渲染成空列表，而服务端渲染看不出来（校验脚本已预加载全部数据）——所以 `pnpm validate` 会**静态检查每个页面源码**是否声明了数据范围（总览页可用 `@data-summary-only` 显式豁免）。
  - 另有一处已做的清理：`Entry.searchText`（把正文原样再拼一遍的检索文本）改为由 `src/lib/searchText.ts` **按需推导并记忆**，不再随条目存储。注意这省的是运行时内存与重复计算，**省不了发布包体积**——那些字符串本来就在数据里，拼接结果是在浏览器里算出来的。
- **手机端适配**：三档断点 —— ≥900px 用顶栏导航、≤899px 用底部标签栏与「更多」面板、≤560px 单列布局并把正文字号抬到 16px、按钮热区拉到 44px（`btn--sm` 38px、`chip` 36px）、顶栏留出 `env(safe-area-inset-top)` 刘海安全区。
  - **两套导航的断点必须成对**：顶栏在 ≤899px 隐藏，底部标签栏就必须在 ≤899px 显示。曾经写成「顶栏 ≤899 隐藏、标签栏 ≥721 隐藏」，于是 **721–899px（平板竖屏、分屏窄窗口）两个导航同时消失，页面上没有任何入口**。这类缺陷跑类型检查与路由渲染都发现不了，所以 `pnpm validate` 直接解析 `index.css` 校验这一对断点相差 1。
  - 长串英文/公式/无空格内容在卡片内 `overflow-wrap: anywhere`，避免整页被撑出横向滚动。
- **古籍排版**：古诗文支持 `writing-mode: vertical-rl` 竖排；点击诗句即可遮住该句用于自测。
- **无依赖后端**：全部离线，数据存 `localStorage`。
- **现代文阅读原文与范文均为本项目原创撰写**，未摘抄任何现当代作家作品。

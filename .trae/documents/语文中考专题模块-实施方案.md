# 语文「中考专题」模块（按题型逐个攻破）实施方案

## 一、Context：为什么做

用户要求：**按 2027 广州中考大纲 + 过去 5 年真题，总结中考专题，每个专题做专门的讲解和专项训练，达到逐个攻破的效果。**

现状：其他科目都已有各自的「备考模块」，但形态各异、且语文**完全没有**这一类入口：

| 科目 | 现状模块 | 形态 |
| --- | --- | --- |
| 数学 | `math-exam` | 高频题型 + 压轴题策略 |
| 英语 | `eng-topics` / `eng-exam` | 知识模块串讲 / 整卷 |
| 物理·化学·道法 | `phy-exam` / `chem-exam` / `pol-exam` | 题型专题 + 整卷混在同一个模块里 |
| 历史 | `hist-topics` / `hist-exam` | 跨册横向专题 / 整卷 |
| **语文** | **无** | 只有 6 个教材模块 + `/s/chinese/exam` 考点页 |

而 `/s/chinese/exam`（[ExamPage.tsx](file:///d:/workspace/dsh/src/pages/ExamPage.tsx)）是**自下而上**的：把题库的知识点标签聚合成考点，回答「哪个点我有错题」。它不回答「卷面上第几大题考什么、怎么答、我攻破了没有」——这正是本任务要补的**自上而下**的另一半。

## 二、已确认口径（用户决策）

1. **先做语文一科**跑通闭环，其余 6 科后续推广。
2. **每科新建统一的「中考专题」模块**（同科现有的 `*-exam` 之后只保留整卷模拟）。
3. **只做考情归纳（题型/分值/频率/命题角度/评分点）+ 原创仿真题**，不复刻真题原文。
4. **按广州中考题型设专题**（与卷面结构一一对应）。

## 三、方案

### 3.1 模块身份

| 项 | 值 |
| --- | --- |
| 模块 id | `zh-topics` |
| 名称 / 图标 / 主题色 | 中考专题 / 🎯 / `#8a6a3b`（与其他科目的「备考色」一致） |

### 3.3 数据契约（新增到 [types.ts](file:///d:/workspace/dsh/src/types.ts)）

```ts
/** 一条「分步讲解」：把方法拆成先做什么、再做什么 */
export interface ChineseExamStep {
  heading: string;
  body: string;
  /** 示范（可选）：按这一步的方法完整做一遍给看 */
  demo?: string;
}

/** 近 5 年考情的一条（归纳表述，不复刻真题原文） */
export interface ChineseExamTrend {
  /** 年份，如「2025」 */
  year: string;
  /** 这一年的考查形态、分值区间与选材倾向 */
  note: string;
}

/**
 * 一个「中考专题」：按广州中考语文**卷面题型**设专题，
 * 内容是「考情归纳 + 专门讲解 + 专项训练」。
 */
export interface ChineseExamTopic {
  id: string;
  grade: GradeOrAll;          // 一律 'all'：专题是初三总复习，不归属某一册
  title: string;
  /** 卷面定位，如「第二大题之一 · 古诗文积累与默写（约 8—10 分）」 */
  paper: string;
  /** 一句话：这个专题在考什么、拿分靠什么 */
  summary: string;
  /** 近 5 年考情（恰好 5 条，一年一条） */
  trends: ChineseExamTrend[];
  /** 五年趋势结论：一句话说清「现在怎么考、往哪走」 */
  trendSummary: string;
  /** 命题角度：复用历史/道法同一套类型（angle + years + detail） */
  angles: HistoryExamAngle[];
  /** 分步讲解 */
  steps: ChineseExamStep[];
  /** 答题模板：可直接背下来套用 */
  templates?: { name: string; items: string[] }[];
  /** 评分点／踩分点：写成「写到什么才给分」 */
  scoring?: string[];
  /** 易错与失分 */
  pitfalls?: { wrong: string; right: string; why: string }[];
  /** 专项训练分组（`name` 同时是题目上的标签，用于分组刷题） */
  drills: { name: string; note: string }[];
  /** 专项训练题库（每题至少带一个 `drills` 里的标签） */
  questions: QuizQuestion[];
}

export interface ChineseExamTopicEntry extends EntryBase {
  moduleId: 'zh-topics';
  data: ChineseExamTopic;
}
```

同时：`ChineseModuleId` 增 `'zh-topics'`；`Entry` 联合类型增 `ChineseExamTopicEntry`。复用 `HistoryExamAngle` 与既有的 `{ wrong; right; why }` 形状——道法/物理/化学早就跨学科复用这两者，不新造同义类型。

### 3.4 每个专题的内容规格（校验器会把这些变成硬断言）

| 字段 | 下限 | 说明 |
| --- | --- | --- |
| `trends` | 恰好 5 条 | 2021—2025，一年一条；写考什么形态、多少分，不抄题 |
| `angles` | ≥ 4 条 | 命题角度（考情归纳的核心） |
| `steps` | ≥ 4 步 | 每步 `heading` + `body` 非空 |
| `templates` | ≥ 2 组 | 每组 `items` ≥ 3 条（可直接背） |
| `scoring` | ≥ 5 条 | 阅卷踩分点 |
| `pitfalls` | ≥ 3 条 | 易错与失分 |
| `drills` | ≥ 3 组 | 每组的 `name` 至少被 1 道题的 `tags` 命中 |
| `questions` | ≥ 20 道 | 每题至少命中 1 个 `drills` 名；其中简答题（带 `rubric`）≥ 5 道 |

题目 id 规范：`${entryId}-q01`…（全局唯一即可）。条目 `tags` 为 `[专题名, '中考专题']`——模块页筛选行因此只出现 7 个专题名（`tags[0]` 是主标签），不会被 drill 名刷屏。

2. ① **五年考情**（`trends` 表 + `trendSummary` 结论）

| --- | --- | --- |

### 3.6 「逐个攻破」的判定

把 `'zh-'` 加进 [progress.ts](file:///d:/workspace/dsh/src/lib/progress.ts#L26) 的 `ALL_QUESTIONS_PREFIXES`，于是 `zh-topics` 走 **`all-questions`（全题过关）** 策略：

- 每个专题的**每一道题都曾答对**才算「攻破」，答错后再答对同样算过关；
- 列表页与详情页显示「过关 x/y」，并提供「只练没过关的题」。

选它的理由：用户要的是「逐个攻破」，需要一个**可验证的终点**；若沿用 `rate`（正确率 80%）策略，20 道题答对 16 道就算掌握，剩余 4 道从未见过——恰恰是「没攻破」。代价是标准更高，但专题是总复习内容，题量本就有限。

## 五、假设与决策

1. **模块 id 用 `zh-topics`**：`exam` 被考点子页面占用；`zh-` 前缀同时服务于掌握判定的前缀规则。
2. **条目 `grade` 一律 `'all'`**：专题是初三总复习内容，跨册。ModulePage 的 `effectiveGrade` 自动适配逻辑对 `'all'` 条目天然安全（不会被筛空）。
3. **只做考情归纳 + 原创仿真题**：`trends` 逐年一条写成「考查形态 + 分值区间 + 选材倾向」的归纳表述，不引用真题原文、不写具体题目。
4. **不改「本科工具」区**：中考专题是模块，按模块规则出现在学科页「模块」区与模块统计里（`toolsOf` 只放背诵/错题本/考点/知识拓展，见 [SubjectPage.tsx](file:///d:/workspace/dsh/src/pages/SubjectPage.tsx#L22-L53)）。
5. **不改 `PracticePage` / `ModulePage` / `buildQuiz`**：专项训练与攻破清单全部复用 `itemId` / `tag` / `ids` 三个既有入口。
6. **不加入 `LESSON_MODULES`**：课时思维导图只要求语文原有 6 个模块「每课都有」，中考专题不适用。
7. 提交时一并包含上一轮「背诵补齐」尚未提交的 5 个文件（`pnpm gen` 会再次触碰 `summary.ts`），提交信息覆盖两件事。
